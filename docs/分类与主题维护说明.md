## 1. 为什么要改

原来的博客是 AstroPaper 模板原样，有两个明显问题：

1. **文章没有「分类」这个维度**。只有 `tags`（多标签），标签多而碎，读者点进去经常只有一两篇，起不到「按领域浏览」的作用。参考阮一峰博客的做法，需要一个右侧常驻的分类目录，让读者随时知道「这个站有哪些领域、当前这篇属于哪个」。
2. **排版不适合中文阅读**。原模板把 `Google Sans Code`（等宽字体）套在全站正文上，中文只能回退到雅黑，中英混排字宽不齐；而且 Google Fonts 在国内经常加载失败，首屏会闪烁回退字体。配色也是模板默认的暖色调，和「简洁技术博客」的定位不太搭。

所以这次做了两件事：**加分类**（功能）+ **重做视觉**（字体、配色、留白），同时顺手修掉站点域名写错的问题。

## 2. 新增了什么功能

### 2.1 右侧分类栏

- 出现在**文章详情页**和**分类归档页**，宽度 ≥1024px（`lg`）时显示，手机上隐藏。
- 固定在视口内滚动（sticky），文章很长也不会跑掉。
- 当前所属分类高亮（蓝色文字 + 淡蓝底），顶部「全部文章」带总数。
- 每一项后面的数字是该分类已发布文章数；**没有文章的分类数字为 0、颜色变淡**，但仍然显示。
- 分类栏本身不参与站内搜索索引（`data-pagefind-ignore`），避免搜索结果里重复出现分类名。

### 2.2 分类总览页 `/categories/`

一页列出全部分类：分类名 + 一句话说明 + 文章数（没有文章显示「暂无文章」）。导航栏「分类」入口指向这里。

### 2.3 分类归档页 `/categories/<分类>/`

列出该分类下所有文章，分页（每页 4 篇，跟首页一致），面包屑形如「分类 › 运维部署」。空分类也有页面，显示「这个分类还没有文章，写一篇就会出现在这里」，不会 404。

### 2.4 分类清单由你手动维护

分类**不再从文章里自动汇总**，而是集中写在 `src/data/categories.ts` 一个数组里。好处是：

- 可以先把分类框架定好，慢慢往里填文章，空分类也正常显示；
- 顺序固定，不会被「谁文章多谁排前面」打乱；
- 改名、删除、加说明都只改这一个文件，不用碰任何页面代码。

### 2.5 视觉与字体

- **浅色主题（苹果白）**：纯白底 `#ffffff`、近黑正文 `#1d1d1f`、单一系统蓝强调 `#0066cc`、边框 `#e3e3e6`。目标就是干净、克制，只有链接和交互点用蓝色。
- **深色主题（保留橙色）**：深蓝灰底 `#212737` + 橙色强调 `#ff6b01`。试过把深色也换成蓝色，观感太闷，最终保留橙色做暖冷对比。
- **字体（思源黑体）**：自托管 `Noto Sans SC` 三个字重（300/400/700），每个约 100KB，只包含站内实际用到的字符（子集化）。正文 400、标题 300 + 收紧字距，靠字号建立层级而不是靠加粗。等宽字体只给代码块，正文不再用等宽。
- **排版**：正文行高 1.9（中文长文更好读），正文宽度 768px（`max-w-app`），带侧栏的页面外层放宽到 1024px（`max-w-wide` = 768px 正文 + 208px 侧栏 + 48px 间距），正文本身还是 768px，不跟着变宽。

### 2.6 站点域名修正

`site.url` 原来是模板作者的 `https://astro-paper.pages.dev/`，导致 canonical、og:url、sitemap、RSS 全部指向别人的域名（SEO 上等于把权重送人）。现已改为 `https://tonyblog-ex7.pages.dev/`。

## 4. 几个设计决策的原因（踩过的坑）

**为什么 `category` 是单值、`tags` 还是多值？**
分类是「一篇只属于一个地方」的导航维度，多值会让侧栏统计重复、也说不清哪篇该出现在哪。标签继续承担「多角度打标」。

**为什么要单独一个 `categories.ts`？**
早期版本从文章里自动汇总分类，结果满站只有 5 篇文章、5 个分类，等于没分类。手动清单能把「以后要写的方向」先摆出来。

**为什么空分类要单独写路由？**
Astro 的分页函数 `paginate([])` 遇到空数组不会产出任何页面，空的分类点进去就是 404。所以归档页对「没有文章的分类」单独返回一条不带 `page` 的路由，模板里 `page` 做成可选，只对有文章的列表渲染文章和分页。

**为什么正文不跟着变宽？**
两栏布局用外层放宽、正文列保持 768px 的方式：中文单行超过 40 字左右就开始难扫读，侧栏占的是外部空间，不能挤压正文的阅读宽度。

**为什么字体要自托管 + 子集化？**
国内访问 Google Fonts 不稳定，用系统字体又会让标题字重在 Windows/macOS 上不一致。子集化后每个字重 100KB 左右，比完整版（中文动辄 5MB+）小得多，还能控制「宋体标题看不到真粗体」这类问题——所以标题用 300 字重 + 大字号，不做伪加粗。

**为什么深色主题不跟浅色统一成蓝色？**
试过 `#4d9fff`，在深蓝灰底上偏灰、发闷，整页像蒙了一层雾。橙色在深底上对比强、有精神，就保留了。两套主题冷暖对比是刻意的，不是没统一。

## 5. 日常写文章

### 5.1 步骤

1. 在 `src/content/posts/` 新建文件，文件名就是 URL（中文可以，建议短一些），例如 `Redis缓存击穿处理.md`。
2. 粘贴下面的 frontmatter，改掉标题、时间、分类、标签、摘要。
3. `npm run dev` 本地看效果（默认 http://localhost:4321）。
4. 提交推送，Cloudflare Pages 自动部署。

### 5.2 frontmatter 模板

```yaml
---
author: "Tony"
pubDatetime: 2026-11-21T10:00:00+08:00
title: "文章标题"
featured: false
draft: false
category: "开发笔记"
tags:
  - Redis
  - 缓存
description: "一句话摘要，会显示在列表页、RSS 和搜索结果里。"
---
```

### 5.3 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 文章标题 |
| `pubDatetime` | 是 | 发布时间，必须带时区偏移，如 `+08:00`；**未来时间会被当作定时文章，不到点不显示** |
| `description` | 是 | 摘要，列表页/RSS/搜索都用它，写一句具体的 |
| `category` | 否 | **单值**，必须和 `categories.ts` 里的 `name` 完全一致（含空格）。不写 = 归到「未分类」 |
| `tags` | 否 | 多值数组，随意的技术关键词，会进标签页 |
| `featured` | 否 | `true` 会出现在首页「精选文章」 |
| `draft` | 否 | `true` 草稿，构建时完全不输出 |
| `modDatetime` | 否 | 修改时间，填了会显示「更新于」 |
| `ogImage` | 否 | 自定义分享图；不填用默认图 |
| `hideEditPost` | 否 | `true` 隐藏文章底部的「编辑页面」链接 |
| `canonicalURL` | 否 | 原文转载地址 |

### 5.4 小贴士

- **分类名写错不会丢文章**：写了一个清单里没有的分类，它会自动追加到侧栏末尾（按文章数排序），不会报错也不会隐藏。看到侧栏尾部多出一个陌生分类，就是笔误。
- **`category` 只能写一个**。写成数组会直接构建失败（schema 校验不过）。
- **`tags` 不要和分类重复**。分类已经在侧栏了，标签留给更细的关键词。
- 文件名带空格和特殊符号会被转义成 `%20` 之类，建议用中文或英文短词，不加空格。

## 6. 维护分类

所有分类操作都在 **`src/data/categories.ts`** 里完成。

### 6.1 新增分类

```ts
export const categoryDefinitions: CategoryDefinition[] = [
  { name: "开发笔记", description: "前端、后端、框架与语言特性" },
  { name: "读书笔记", description: "技术书与闲书的摘记" }, // ← 新增一行
];
```

保存后，侧栏、`/categories/`、归档页都会自动出现，**不用改任何页面代码**。还没文章时显示「暂无文章」，等第一篇文章写上这个分类，数字自动变 1。

### 6.2 改名

直接改 `name`。注意两点：

1. 该分类下所有文章的 `category` 要改成新名字，否则它们会掉到「未分类」。
2. URL 由 `name` 生成，改名后旧链接（`/categories/旧名/`）会失效。

### 6.3 删除分类

从数组里删掉即可。如果还有文章写着这个分类，它会自动补在侧栏末尾，文章不会丢——但建议同时把这些文章的 `category` 改到别的分类。

### 6.4 调顺序

数组顺序就是侧栏和总览页的顺序。把常用的放前面，`未分类` 永远排在最后（代码里固定）。

### 6.5 自定义 URL（可选）

分类名带空格或想用英文地址时，加 `slug`：

```ts
{ name: "AI 应用", slug: "ai", description: "大模型、智能体与业务落地" }
```

访问地址就是 `/categories/ai/`。**已上线的分类不要改 slug**，否则旧链接 404（要改的话记得在 Cloudflare 配重定向）。

### 6.6 分类说明（可选）

`description` 只显示在 `/categories/` 总览页，侧栏不显示。一句话，别超过 20 字。

## 7. 字体：写了生僻字怎么办

字体是按「站内出现过的字符」裁剪的子集，所以新文章里如果用了从没出现过的汉字，可能没有字形，会回退到系统雅黑——不会乱码，但同一个字粗细会和周围不一致。

处理办法：

```bash
npm run font:check   # 纯 Node，列出哪些文件里有字体没覆盖的字符
npm run font:build   # 需要 Python + fontTools，重新生成子集
```

`font:build` 会扫描 `src/` 全部内容（含文章）和根目录的 `*.ts` / `*.json` 配置，重新裁剪并覆盖 `public/fonts/*.woff2`，然后记得一起提交字体文件。第一次运行需要下载思源黑体源文件（缓存在 `.cache/fonts`），之后可离线。

日常写技术文章基本不会遇到，遇到 `font:check` 报出来再处理即可。

## 11. 常见问题

**Q：侧栏为什么在手机上不显示？**
A：宽度不足 1024px 时隐藏，避免挤压正文。手机端从顶部导航「分类」进总览页，功能一样。

**Q：为什么新文章没出现在首页？**
A：检查三个地方——`draft: true`、`pubDatetime` 写成了未来时间、或者文件在 `src/content/posts/` 之外（以 `_` 开头的文件/目录也会被忽略）。

**Q：分类页的顺序和我想的不一样？**
A：只按 `categories.ts` 数组顺序排；「未分类」永远最后；未登记的笔误分类追加在末尾。想调顺序就改数组顺序。

**Q：改完没反应？**
A：`npm run dev` 对 `src/` 下的改动是热更新的；改了 `astro-paper.config.ts`（域名、站点标题这类）需要重启 dev 服务器。线上以 `git push` 后 Cloudflare 的构建结果为准。
